# Thiệp Cưới Online — Wedding Invitation Site

A self-contained, static Vietnamese wedding invitation website — envelope-opening intro,
background music, countdown timer, save-the-date calendar, family info + a personalized
"Thư Mời Cưới" invitation letter, couple profiles, photo gallery with lightbox, gift/bank
QR codes, and a wishes wall — plus **personalized invitation links** per guest (e.g.
`/for/chi-lien-cung-nguoi-thuong` → "Kính mời chị Liên cùng người thương").

No build step, no framework, no server required. Pure HTML/CSS/JS, ready to host on
**GitHub Pages** for free.

## 1. Customize your content

Almost everything is in two files:

- [`data/config.js`](data/config.js) — couple names, family/parents info, wedding date,
  ceremony schedule, foreword letter, gallery images, bank/QR gift info, music file, and
  SEO text.
- [`data/guests.js`](data/guests.js) — the guest list that powers personalized links.

Open each file and edit the values — they're plain JavaScript objects with comments
explaining every field.

### Photos & gallery

`data/config.js` currently points `couple.groom.photo`, `couple.bride.photo`,
`gallery`, and `seo.image` at real (free-to-use, Unsplash) wedding photography, so the
site looks finished out of the box. Replace them with your own:

- Easiest: upload your photos anywhere that gives you a direct image URL (e.g. an
  Imgur/Cloudinary link, or a photo host of your choice) and paste that URL in.
- Or: put files under `assets/img/` (e.g. `assets/img/groom.jpg`) and point the config
  field at `assets/img/groom.jpg` instead of a URL — both local paths and full URLs
  work anywhere an image is referenced in `data/config.js`.
- `gallery` is an array — add/remove entries freely, the album grid follows its length.
- `seo.image` is the thumbnail shown when the link is shared on Zalo/Facebook/Messenger
  (1200×630 recommended).

### Gift QR codes

QR codes are **generated automatically** (via the free api.qrserver.com service) from
`gift.groom` / `gift.bride`'s `bankName`, `accountNumber`, and `accountName` in
`data/config.js` — there's no QR image to create or replace. Edit those three fields and
the QR on the page updates itself to match. If you'd rather use your bank app's own
official VietQR image instead, add a `qr: "assets/img/your-file.png"` (or a URL) field
to that gift entry — `qrUrlFor()` in `assets/js/app.js` falls back to generating one
only when `qr` isn't set.

### Background music

`assets/audio/background-music.mp3` plays automatically the moment a guest taps "Mở
Thiệp Mời" (opening the envelope counts as the user gesture browsers require before
audio can autoplay), and can be toggled anytime with the floating button in the
bottom-right corner. It starts at `music.startAt` seconds (currently `50`, set in
`data/config.js`) the first time it plays each visit, then behaves like a normal
play/pause toggle afterwards. Set `startAt` to `0` to always start from the beginning.

To swap the track, replace `assets/audio/background-music.mp3` with your own file
(same filename), or point `music.src` in `data/config.js` at a different path — just
make sure you have the rights to use whatever track you pick.

## 2. Personalized invitation links

Every guest gets their own greeting via a clean URL:

```
https://yoursite.com/for/chi-lien-cung-nguoi-thuong
→ renders "Kính mời chị Liên cùng người thương"
```

To add a guest, add an entry to `window.GUEST_LIST` in `data/guests.js`:

```js
{
  slug: "chi-lien-cung-nguoi-thuong", // the URL segment
  title: "chị",                       // anh / chị / cô / chú / bác / ông / bà / ""
  name: "Liên",
  companion: "cùng người thương",     // or "và gia đình", or "" for none
}
```

The greeting is built as `Kính mời {title} {name} {companion}`. For anything that
doesn't fit that pattern, set `greeting: "..."` on the guest entry to override it
completely.

After editing `data/guests.js`, **regenerate the personalized pages**:

```bash
npm run generate
# or directly: node scripts/generate.js
```

This creates a real `for/<slug>/index.html` file per guest (see "How personalized
links + link previews work" below) — commit and push these generated files along with
your `data/guests.js` change, or the new/edited guest links won't be live yet.

Open **`admin.html`** (e.g. `https://yoursite.com/admin.html`) after publishing to get a
copy-paste list of every guest's full link — handy for sending out invites. This page is
for you, the organizer; there's no need to share it with guests.

### How personalized links + link previews work

Each guest in `data/guests.js` gets a **real, pre-built page** at `for/<slug>/index.html`
(generated by `scripts/generate.js`), with the correct `<title>` and Open Graph tags
baked directly into the HTML:

```
https://yoursite.com/for/chi-lien-cung-nguoi-thuong
→ page title / link-preview card: "Thân mời chị Liên | Ngày chung đôi"
   subtitle: "đến dự buổi tiệc chung vui cùng gia đình"
→ on-page greeting after opening the envelope: "Kính mời chị Liên cùng người thương"
→ "Thư Mời Cưới" section further down: "TRÂN TRỌNG KÍNH MỜI CHỊ LIÊN CÙNG NGƯỜI THƯƠNG"
```

This matters because apps like Zalo, Messenger, and Facebook generate their link-preview
card by reading plain HTML meta tags — they don't run JavaScript — so a purely
client-rendered greeting would never show up in a shared link's preview. Baking it into
a real file per guest fixes that while staying fully static.

Any slug typed in a browser that *isn't* in `data/guests.js` still resolves correctly
(via the `404.html` → `index.html` redirect trick below), it just won't have a
personalized preview card — only the generic default title/description.

> **How the clean `/for/<slug>` URLs work for guests not in the generated list:**
> GitHub Pages only serves static files. `404.html` catches any unknown path and
> forwards it to `index.html`, which restores the original URL and renders the right
> guest client-side — a standard technique for client-side routing on GitHub Pages.
> It also transparently handles the repo's subpath (e.g. `/To_quang_khai_wedding/`), so
> you don't need to configure anything for it to work.

## 3. RSVP / wishes

By default, guest wishes are saved in each visitor's own browser (`localStorage`) and
shown on the page instantly — no backend needed. If you'd like wishes sent to you (email
or a spreadsheet), set `rsvp.endpoint` in `data/config.js` to a webhook URL from a free
service such as [Formspree](https://formspree.io) or a
[Google Apps Script web app](https://developers.google.com/apps-script/guides/web) bound
to a Google Sheet. Wishes keep saving locally either way, as a fallback.

## 4. Run it locally

Because all data loads via `<script src="...">` tags (not `fetch`), you can simply
double-click `index.html` to preview it — no local server required. To preview the
personalized `/for/<slug>` links locally, run a tiny static server instead, e.g.:

```bash
npx serve .
# or
python -m http.server 8080
```

## 5. Deploy to GitHub Pages

This repo is published at **https://github.com/ntuan7059/To_quang_khai_wedding**, live at:

**https://ntuan7059.github.io/To_quang_khai_wedding/**

(No custom domain — GitHub Pages project URLs are always `<username>.github.io/<repo>`;
the username can't be dropped without either a custom domain or renaming the GitHub
account itself.)

To (re-)deploy after making changes:

```bash
npm run generate            # rebuild for/<slug>/index.html from data/guests.js
git add .
git commit -m "Update invitation"
git push
```

One-time setup (already done for this repo, kept here for reference): on GitHub,
**Settings → Pages → Build and deployment → Source: "Deploy from a branch"**, branch
`main`, folder `/ (root)`.

> If you ever move this to a custom domain, add a `CNAME` file with the domain name and
> configure DNS per
> [GitHub's custom domain docs](https://docs.github.com/en/pages/configuring-a-custom-domain-for-your-github-pages-site) —
> the `/for/<slug>` links keep working either way, since `404.html` and `index.html`
> compute the base path from the current URL rather than assuming a subpath.

## Project structure

```
index.html              main invitation page (single page app)
404.html                GitHub Pages SPA-routing redirect for unlisted /for/<slug> links
admin.html              organizer-only page listing every guest's shareable link
scripts/generate.js     builds for/<slug>/index.html per guest (run after editing guests.js)
for/<slug>/index.html   generated personalized pages — do not hand-edit, re-run generate.js
data/config.js          couple, wedding, gift, music, SEO, calendar/quote/foreword config
data/guests.js          guest list for personalized links
assets/css/style.css    all styling & animations (white/cream base, maroon + gold accents)
assets/js/app.js        rendering, countdown, calendar, envelope, music, gallery, QR, icons
assets/img/             favicon only — every photo and background texture is a hosted URL
assets/audio/           background-music.mp3
```

## Notes

- This project was built from scratch as an original implementation of the common
  Vietnamese "thiệp cưới online" invitation format (envelope intro, music, countdown,
  gallery, gift QR, wishes wall) — it does not reuse code or assets from any specific
  existing invitation site.
- Couple/gallery photos ship pointing at real Unsplash photography (free to use) so the
  page looks finished immediately; swap them for your own before sharing the link with
  guests (see "Photos & gallery" above).
- Icons (calendar, map pin, music note, the small flourish in "Nhà Trai ⟡ Nhà Gái") are
  hand-rolled inline SVGs in `assets/js/app.js` (the `ICONS` object) rather than emoji,
  so they render identically everywhere instead of depending on the visitor's device
  having matching emoji glyphs.
- `for/*/index.html` files are generated, not hand-written — always edit
  `data/guests.js` and re-run `npm run generate`, don't edit files under `for/` directly
  (they'll just get overwritten next time).
